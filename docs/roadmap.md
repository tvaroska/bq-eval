## Next Horizons (`v0.2.0`)

- [ ] **M5 — Reformulate `bq-eval` Around Dual-Path Ingestion (`BQAA` Light Path + OpenTelemetry `_AllSpans` Enterprise Path) -> Single Evaluation & FinOps Engine** *(detailed design note: [`docs/bqaa-and-dual-path-architecture.md`](bqaa-and-dual-path-architecture.md))*:
  - **1. Positioning & Narrative Reformulation (`README.md`, `AGENTS.md`, `docs/architecture-and-sql.md`)**:
    - Reframe `bq-eval` explicitly as an **expansion and FinOps/Governance layer built on top of BigQuery Agent Analytics (`BQAA`)**: developers use 1-line `BigQueryAgentAnalyticsPlugin` (`google-adk[bigquery-analytics]`), `BigQueryCallbackHandler` (`langchain-google-community[bigquery]`), or BigQuery Conversational Analytics conversation logging to stream raw events into `agent_events` via the BigQuery Storage Write API (with standard OpenTelemetry `_AllSpans` retained for non-ADK and multi-cloud agents), and then drop `bq-eval` (`Step 1 -> Step 2 -> Step 2.5 Skill -> Step 3`) directly on top of `agent_events` inside BigQuery.
  - **2. Zero-Copy `BQAA` Adapter Views (`sql/bqaa_adapter_views.sql`)**:
    - Map `BQAA`'s auto-created `agent_events` table (`timestamp`, `event_id`, `event_type`, `agent`, `session_id`, `invocation_id`, `trace_id`, `span_id`, `parent_span_id`, `content` JSON, `content_parts` Object Table refs, `attributes.usage_metadata`, `latency_ms` JSON, `status`, `error_message`) and pre-built `v_llm_request` view onto `bq-eval`'s span waterfall and payload contract, including automatic `event_id` deduplication for Storage Write API retries and mapping of `USER_MESSAGE_RECEIVED`, `AGENT_RESPONSE`, `LLM_RESPONSE`, and `TOOL_*` events.
  - **3. Dual-Mode SQL Evaluation (`AI.GENERATE_TABLE` Today + `AI.EVALUATE_AGENT` Ready)**:
    - Keep 100% in-warehouse SQL execution via `AI.GENERATE_TABLE` (avoiding pulling `agent_events` out into a separate Python `GraderPipeline` client) while adding `eval_session` / `eval_turn` compatibility views and `AI.EVALUATE_AGENT` (`managed_metrics`) recipes to [`sql/step2_stateless_eval.sql`](../sql/step2_stateless_eval.sql) and [`skills/bq-eval/references/sql_recipes.md`](../skills/bq-eval/references/sql_recipes.md).
  - **4. Four Enterprise Capabilities Added on Top of Base `BQAA`**:
    - **Day-1 Cost per Verified Outcome (`CPVO`) & Context-Cliff FinOps**: Convert `BQAA`'s raw `attributes.usage_metadata` token counts (`prompt`, `completion`, `thoughts_token_count`, `cached_content_token_count`) into span-level `<=200K` vs. `>200K` (`7.5x` output) USD costs, 4-bucket traffic attribution, `1/N` prefix-cache dilution diagnostics, and `FOCUS 1.2` Utilized vs. Idle Provisioned Throughput chargeback.
    - **3-Tier Eval FinOps (`90–95%` Judge Cost Reduction)**: Pre-filter `agent_events` with `$0` Step-1 SQL health checks and route only a deterministic `5–10%` `FARM_FINGERPRINT(trace_id)` canary + `100%` error tail to LLM judges during off-peak Provisioned Throughput valleys.
    - **Statistical Judge Calibration & Regression Gates**: Layer conditional **Rogan-Gladen / PPI** prevalence-bias correction (95% confidence intervals), **Gwet's `AC2 >= 0.80`**, fail-closed `NULL` (`UNJUDGED`) guards, and `0%` negative-flip paired run comparisons (`v_step3_paired_run_comparison`) over raw judge verdicts.
    - **Plain-English `bq-eval` Skill Over `agent_events`**: Extend [`skills/bq-eval/SKILL.md`](../skills/bq-eval/SKILL.md) so coding agents can author new 4-point rubrics and run custom slice evaluations (`5%`, `last 1 hour`, per-agent outliers) directly against `BQAA`'s `agent_events` table.
- [ ] **M6 — Live BigQuery Continuous Query & Looker Studio / Cloud Run Scorecard Viewer**:

- [ ] **M7 — Agentic Trajectory Triage, Defect Lifecycle & Skill `EVAL.yaml` (`google/adk-recipes` Alignment)**:
  - **Elided Trajectories & Sandboxed `jq` Reviewer (`ambient-quality-agent` patterns):** Compress oversized trace strings and duplicate blocks into `{"$elided": ...}` / `{"$same_as": ...}` stubs paired with a bounded subprocess `query_trajectory` `jq` inspector (`timeout`, output page cap, concurrency semaphore) for trajectories that overflow single-pass judge windows (complementing `$0` `Rule 0` SQL pre-gates and Rogan-Gladen/Gwet's `AC2` calibration).
  - **Stateful Defect Insights & Canonical BQ Capture Preference:** Cluster recurring failures into tracked insights (`NEW | RECURRING | RESOLVED`, 14-day auto-resolve, `OccurrenceState`: `TRACKED | REJECTED | UNJUDGED`), keep clustering tables joined via left-join rather than mutating append-only trace tables, and rank duplicate stored trajectories preferring earliest complete capture (`(status = 'ingested') DESC, created_at ASC`).
  - **Declarative Skill `EVAL.yaml` & Fail-Closed Execution:** Pair [`skills/bq-eval/SKILL.md`](../skills/bq-eval/SKILL.md) with declarative `EVAL.yaml` assertions (`MUST`/`SHOULD` rubric checks + deterministic `tool_called` / zero-hallucination gates), raise an explicit gate error if `scored == 0`, and enforce strict `execution in ("local", "remote")` validation plus atomic config-last publishing for custom evaluator definitions.
- [ ] **M8 — End-to-End `insurance-agency` Case Study: From Raw `Cost per Task` to Full `Cost per Validated Outcome (CPVO)`**:
  - Ingest real multi-service UK AISI Inspect `.eval` OpenTelemetry traces, 35-table SQLite/PostgreSQL state-diff verdicts, and hard E&O compliance gates from `insurance-agency` into `bq-eval`.
  - Demonstrate the 3-tier FinOps progression on live multi-model benchmark data (`gemini-3.8-flash`, `claude-sonnet-5-5`, `DeepSeek-V4.1-Flash`): (1) **Raw Cost per Task / Attempt**, (2) **Cost per Deterministic Outcome** (`60%` DB state diff + `40%` OTLP trace + hard E&O gate), and (3) **Full Cost per Validated Outcome (`CPVO`)** combining 4-bucket USD spend (`production_inference` + `conflict_escalation` + `agent_gym_eval` + `autorater_judge`) with Rogan-Gladen calibrated communication rubric pass rates ($\hat{\theta}_{\text{RG}}$).
