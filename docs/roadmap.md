# Roadmap (`bq-eval`)

## Where we are

`bq-eval` `v0.2.2` ships a zero-debt (`54` tests, `mypy --strict` across `21` source files, `ast-grep` `Rule 0` firewall) Dual-Path BigQuery SQL and offline SQLite evaluation and FinOps engine over Light Capture (`BQAA` `agent_events`) and Full Capture (`OTel` `_AllSpans`), validated on `343` live multi-agent runs (`m2-live-20261113b`). Active showcase-graduation work closes three milestone tracks: (1) `StratPPI` tail-sampling debiasing, SQLite multi-app parity, `eval_results` deduplication, Engine B quota/pricing accounting, `EVAL-P10` rubrics + `EVAL.yaml`, and rubric/tag sync (`M6` / `v0.2.3`); (2) a `.stitch/DESIGN.md`-governed GM3 Light `bq-eval serve` workbench backed by committed empirical receipts and verified `capacity`/`docubridge` wire contracts (`M7` / `v0.3.0`); and (3) one-command standalone BigQuery/Terraform bootstrap code targeting a single co-located `Showcases` GCP project alongside `docubridge` and `docubridge-examples`, held ready locally without deploying yet (`M8` / `v0.4.0`). A daily review on `2026-11-21` added `F1`–`F21` to `M6` and `M7`: two wrong-number defects in shipped SQL (`F1` pricing fallback, `F2` paired-run ordering) and missing value tests on the BigQuery views (`F3`, `F4`).
