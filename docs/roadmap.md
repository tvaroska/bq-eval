# Roadmap (`bq-eval`)

## Where we are

`bq-eval` `v0.3.0` (`M7`, shipped) plus `M8`, `M9`, `M10-1`/`M10-2` (`M10-3` plumbing only), and `M11` (**implemented locally, pending release**) deliver an offline-verified (`157` tests, `mypy --strict`, `ast-grep` folder-level `Rule 0` firewall, `standards_debt.json = 0`, `73` dry-run manifest statements) Dual-Path BigQuery SQL and SQLite evaluation and FinOps engine over Light Capture (`BQAA` `agent_events`) and Full Capture (`OTel` `_AllSpans`, `39`-col parity), cold-start `bq-eval bootstrap --mode light|full|hybrid`, standalone/co-located single-project `terraform/` + non-root `Dockerfile`, 1P/3P cache-write & Priority/Flex PayGo pricing, `RL-1`–`RL-5` governance, 3-Pool Hourly `FOCUS 1.2` + `capacity` `BQ-G1` wire contracts, BigQuery Omni zero-egress spokes, `/interactions` session lineage, 5-minute SLO/`429` breaches, `RingBufferSpanExporter`, `ATIF-v1.8` loss-bank export, and clause-scoped `EVAL-P09` `policy_sha256` `NFR == 0.0%` gates. What remains open before `v0.6.0` is `M10-3` live empirical execution (real `N >= 100` blind dual-human SME labeling + live GCP BigQuery proof runs; live `terraform apply` held for explicit operator sign-off; container build & Trivy scan run in Cloud Build because `docker`/`trivy` are absent locally). Open after the 2026-11-23 review: `M13` and `M14` (five `P0` wrong-number defects, one visible in demo output).
