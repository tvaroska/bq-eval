# Silver

> How the Silver views and bounded incremental tables are produced. The contract they meet is [specs/silver.md](../specs/silver.md).

## From telemetry shapes to `spans`

The trace store holds telemetry in up to three [shapes](../specs/shapes.md). Over a shared `_AllSpans` table, `spans(from_time, to_time)` routes shapes in **one single `SELECT` pass** (`CASE WHEN` marker checks rather than `UNION ALL`, which scans `_AllSpans` `2x`) into a **text-free** base returning window-member traces (`sql/silver/schema/spans.json`). Shape 1 (legacy ADK) keys on `gcp.vertex.agent.llm_request` (`!= '{}'` on tool spans) / `tool_call_args` / `call_llm` (never `invocation_id`); Shape 2/3 key on `gen_ai.input.messages` / `gen_ai.input.messages_ref` / `gen_ai.tool.call.arguments` (`*_ref` selects Shape 3). The content markers decide `shape`; `span_kind` (`model_call | embedding | tool_call | retrieval | memory | agent | workflow | other`) is read from `gen_ai.operation.name` (non-convention zero-token operations like `invoke_node` stay `other`, counted in `span_count`, unflagged), while `is_model_call` marks the innermost span reporting positive tokens (`SAFE_CAST` over JSON-string token counts) or a model/embedding operation — including a tool span reporting positive tokens, which keeps `span_kind = 'tool_call'` in `tool_calls` and also projects to `model_calls` (`ADR-042`, `ADR-045`, `ADR-047`). In ADK Format 1, `call_llm` folds with its inner `generate_content` child: the row keeps the child's ID, times, tokens, and `operation_name`, while lifting `gcp.vertex.agent.llm_request`, `llm_response`, and `session_id` conversation fallback from `call_llm` when absent on the child (`ADR-045`). `embeddings` calls get `content_missing = false`; other model or tool calls without inline content or a reference address get `content_missing = true` and no `trace_payloads` row (`ADR-036`). Gateway and tool-proxy spans are read from their own landing place (`source_class = 'platform'`, carrying `bq_eval.caller_app_id` for caller attribution, `ADR-034`, `ADR-045`). The cloud runtime's own spans (no instrumentation scope, `kind IS NULL`) keep `source_class = NULL` and are skipped when the root is chosen (`ADR-037`). Application lookup checks `apphub.application.id` first, then `(service.name, COALESCE(deployment.environment.name, deployment.environment))`. Custom gateways, coding SDKs (`Claude Agent SDK`), and non-conforming frameworks normalize upstream through the **Bronze / OTel Collector Adapter Port** before landing.

- An adapter maps; it never repairs or invents defaults. Structured/list columns use BigQuery `JSON` (never `ARRAY`) so `NULL` stays distinct from `[]`; child-set counts are `0` when empty, `traces` token sums are `NULL` when `model_call_count = 0`, and subject-less provenance/bound booleans (`identity_attested`, `traffic_type_attested`, `args_hash_attested`, `app_identity_bound`) are `NULL` when their subject is `NULL` (`ADR-045`).
- `spans` keeps one row per `(trace_id, span_id)` per landing place (platform winning cross-place clashes), the latest arrival, and counts duplicates (`ADR-042`).
- Restricted text views (`trace_payloads`, `tool_calls`) join `_AllSpans` and BigLake by `(trace_id, span_id)`; Gold add-ons read the published views below, never `spans` directly.

### Content by reference (BigLake Parquet + Hive partitioning) & Gateway Inline-Artifact Port

For Shape 3, storage sits behind a per-BU-scoped **BigLake external table (`WITH CONNECTION`)** with typed schema `(dt DATE, hr STRING, ref_uri STRING, payload JSON)` over Hive date/hour partitions (`dt=YYYY-MM-DD/hr=HH/...`), using **micro-batched Parquet (`metadata_cache_mode = 'MANUAL'`, `max_staleness = INTERVAL 30 MINUTE`) or Iceberg** as the canonical production format (`jsonl` dev/low-volume only) in the same BigQuery location and CMEK perimeter as the trace. The window functions apply a **static Hive partition predicate** derived from the from-time and to-time, matching the span window, before joining `gen_ai.input.messages_ref` and `gen_ai.output.messages_ref` on `ref_uri` (keeping `system_instructions_ref` and `tool_definitions_ref` as addresses; missing records set the corresponding `*_read_whole` boolean among the 5 payload parts to `false`, `ADR-045`).

Interactive large attachments (`100 MB`) arriving directly at a central gateway never buffer inside SDK telemetry hooks; the **Gateway Inline-Artifact & Guardrail Port** streams files upstream via pre-signed private URLs (`media_uris`, `document_bytes`, `page_count`, `attachment_sha256`) and emits structured `guardrail.intervention` verdicts. Traffic whose content is stored nowhere is kept in the text-free objects and is not scored (`ADR-036`).

## Read windows (`light`) & the design-only high-volume profile (`enterprise`)

BigQuery does not push outer `WHERE` filters past `GROUP BY trace_id` (`37x` scan penalty measured live):

- **`light` (table functions, no stored data, `ADR-035`):** each published object is a table function of a from-time and a to-time. `spans` filters `start_time` to the window plus a margin on both sides, with static Hive `dt` predicates on Shape 3; a trace is a member when its first span starts inside the window, and a trace longer than the margin is flagged. A window has settled when its end, the margin and the settle time have passed; Gold keeps results from settled windows only. Fixed-window views are thin wrappers. Measured on the trace store: a window given as literals or query parameters prunes through the function as plain SQL with the filter inside does, a window read from a table does not, and a function that reads Bronze directly is authorized on it by itself and again after every `CREATE OR REPLACE`.
- **`enterprise` (design only, `ADR-035`):** not decided. Candidate: a scheduled append writes a typed, text-free copy of new spans, selected by arrival time, into one partitioned table, and the same functions run on top of it; nothing is merged or rewritten and text is never copied. Earlier candidate, kept until a side-by-side test chooses: a scheduled BigQuery SQL `MERGE` per published object runs every `5–15` minutes in an isolated slot reservation over `(receive_time_watermark - settle_buffer .. now)` into `DATE(start_time)`-partitioned tables clustered on `(COALESCE(trace_owner_app_id, '__unowned__'), trace_id)`:
  1. Every `MERGE ON` clause mandates a **static target partition-prune predicate** (`target.partition_date >= DATE_SUB(CURRENT_DATE(), INTERVAL merge_lookback_days DAY)`) so late or midnight-straddling spans never rewrite multi-TiB historical partitions.
  2. `outcomes` and session rollups apply explicit bounded lookback windows (`outcome_lookback_days`, `session_inactivity_hours`).
  3. Compaction runs under `max_bytes_billed` ceilings and pre-flight `INFORMATION_SCHEMA.JOBS` slot breakers.

## `model_calls`

Projects text-free LLM and `embeddings` call facts over `spans` (`chat`, `generate_content`, `embeddings`, legacy `call_llm` deduplicated against child `generate_content`, and any other span that reports tokens above zero, innermost only), including `span_id`, `parent_span_id`, `client_request_id` (`x-client-request-id`), `response_id` (`gen_ai.response.id`), `outcome_id`, `trace_owner_app_id`, `agent_id`/`agent_name`, `skill_name`/`skill_version`/`skill_sha256`, `request_model`, `response_model`, `provider`, **`upstream_endpoint_location`**, **`thought_signature_present`**, **`caller_retry_count`** (directly preceding model calls in the same trace, by the same agent for the same requested model, that ended with HTTP `429`), **`state_mode`**, **`runtime_lane`**, **`traffic_type`**, **`traffic_type_attested`**, **`tool_definitions_sha256`**, **`available_tool_count`**, **`selected_tool_names`**, token counts, latency, TTFT, finish reason, HTTP status, `content_missing`, and confidence/cascade facts. Non-LLM time-series/GPU workloads report to a sibling metric table rather than `model_calls`.

## `tool_calls`

Projects `execute_tool`, `retrieval`, and `memory_*` spans enriched with SCD-2 `tools` flags (`writes_state`, `modifies_workspace`, `executes_code`, `sends_external_reply`, `returns_pii`, `creates_ticket`), carrying `authz_mode` (`parameter_matched | token_enforced`), execution-time RFC 8785 `args_sha256` + `args_hash_attested`, `content_missing`, retrieval & memory lineage (`data_source_id`, `acl_dropped_count`, `memory_op`, plus restricted-only `corpus_digest`, `memory_id`, `memory_sha256`, `memory_source_provenance`), warehouse compute (`job_id`, `bytes_scanned`, `bytes_billed`, `slot_ms`), and DevAI/container signals (`sandbox_cpu_sec`, `sandbox_mem_gb_sec`, `sandbox_status`, plus restricted-only `devai_diff_stats`, `devai_test_summary`, `devai_sast_findings`). Server tool spans fold into client parents (or via proxy `mcp.session.id`). Shape-3 `arguments` and `results` read inline span attributes first, falling back to stored model messages matched by `gen_ai.tool.call.id`. `tool_calls_open` never scans restricted Shape-3 buckets and omits `args_sha256`, `arguments`, `results`, `user_id`, `tenant_id`, and the 8 digest/business-key/code-summary columns (`ADR-038`, `ADR-045`); both `tool_calls` and `tool_calls_open` publish `repeat_number` (dense rank of `(tool_name, args_sha256)` inside the trace in order of first `start_time, span_id`). `args_hash_source` (`proxy | silver | application | none`) names where the hash came from: a platform tool-proxy span (`args_hash_attested = true`), Silver's own hash of inline tool-span arguments (`false`), an application `execute_tool` span's `bq_eval.args_sha256` when neither exists (`false`), or `none` (`repeat_number = NULL`); the model's message is never used (`ADR-041`, `ADR-045`).

## `events` & `outcome_links`

`UNION ALL` filtered by `event_time` in `[from_time, to_time)` across the three VPC-SC-isolated copies of `workflow_events` (the system-of-record copy sets `is_authoritative = true`, including CI release services emitting `ci.verified`; the platform copy sets `source_class = 'platform'`; the application/IDE copy sets `source_class = 'application'` and `is_authoritative = false`, including untrusted IDE/app webhooks, `ADR-034`, `ADR-045`), closing spans (`outcome.closed`), span-event `guardrail.intervention` (`control_id`, `control_layer`, `control_action`), `state.transition` (`state_transition_to`: `Guide | Answer`), `model.approved`, SDLC events, and OTel `gen_ai.evaluation.result` (`_AllLogs` `labels` JSON, keyed by `insert_id`). Non-table rows receive deterministic `event_id` keys (`span:<trace_id>:<span_id>` for spans; `insert_id` for logs) under unique `(source_class, event_id)`; within one copy, first `event_time` wins and identical-`event_time` ties break deterministically by canonical row-content lexical order (keeping the 20 fixed columns) while counting conflicts (`ADR-041`, `ADR-047`). Silver lifts `linked_outcome_id`, `outcome_status`, `feedback_reason`, and `state_transition_to` from registered `workflow_events.payload_json` keys (preserving the 20 fixed `workflow_events` columns) and resolves business unit from the trace owner else `outcome.owner` else `'__unowned__'`. Approval and committed-write rows carry `action_args`, hashed via a `65,532`-byte-guarded RFC 8785 BigQuery UDF (`ADR-041`). `events_open` omits `action_args`, both hashes, `payload_json`, `user_id`, `tenant_id`, and `actor_id`. `outcome_links` projects distinct `(primary_outcome_id, linked_outcome_id)` pairs below `events_open` for M:N Gold `CPVO`.

## `trace_payloads`

One row per content-bearing trace (= 1 turn) in `silver_restricted` (`sql/silver/schema/trace_payloads.json`) splitting `prior_history` (`JSON`) from this turn's delta (`turn_prompt`, `turn_context` holding an ordered `JSON` array of tool/retrieval/memory results tagged with `tools` flags, `turn_output`, `step_outputs` `JSON` with `nudge_id`, `media_uris` `JSON` with `document_bytes`/`page_count`/`attachment_sha256`), optional `system_instructions`/`system_instructions_ref` and `tool_definitions`/`tool_definitions_ref` (taken from the first root-agent model call inline, or kept as `*_ref` addresses in Shape 3), and 5 `*_read_whole` booleans (`prior_history`, `turn_prompt`, `turn_context`, `turn_output`, `step_outputs`). Stateful `previous_interaction_id` delta turns leave `prior_history = NULL`.

## `traces`

Groups spans per `trace_id` (`sql/silver/schema/traces.json` and `traces_open.json`) with SCD-2 enrichment (`app_registry`, `tools`, `skill_registry`) and **platform gateway -> root -> earliest-span (`start_time, span_id`)** precedence for multi-span trace attributes (`ADR-040`, `ADR-045`):
1. Caller/desk `trace_owner_app_id` (`bq_eval.caller_app_id` on platform gateway spans taking precedence over proxy service names), `app_identity_bound` (`NULL` when unregistered), `root_span_id` (first application span by `start_time`), `is_turn`, `has_root_span`, 3-principal identity with root `user_id` and `user_id_source`, `identity_attested` (`NULL` when `user_id` is `NULL`), OBO claims, `workspace_session_id`, `previous_interaction_id`, `state_mode`, `runtime_lane`, live A/B keys, optimizer lineage, `mounted_skills` (`JSON`), and `tool_definitions_sha256`.
2. Non-null `0`-defaulted child-set counts (spans, model/tool calls, `mutating_tool_call_count`, `workspace_edit_count`, `unregistered_tool_count`, `guardrail_intervention_count`, `content_missing_call_count`, `user_turn_count`, `duplicate_span_count`, `repeated_tool_call_count`, errors, throttles, and missing-ID span counts) and `NULL`-preserving token totals (`NULL` when `model_call_count = 0`).
3. Completeness: `trace_start_time` with `trace_start_writer`, `missing_parent_count`, `entry_parent_outside`, `exceeds_read_margin` (`ADR-037`), `sampling_probability` (`NULL` when absent), and `last_span_arrival_time`.

## `outcomes`

`outcomes(from_time, to_time)` (`sql/silver/schema/outcomes.json` and `outcomes_open.json`) returns every `outcome.id` with at least one trace or event inside `[from_time, to_time)`, aggregating its traces and events across `[from_time - outcome_lookback_days, to_time + read_margin)` and setting `extends_outside_window = true` when activity lies outside `[from_time, to_time)` (`ADR-045`). Multiple `outcome.closed` records select the winner by authority (`system_of_record > platform > application`), then earliest `event_time` (tie-break `event_id` asc); Silver stays stateless across windows and Gold deduplicates multi-day outcomes by `outcome_id` (`ADR-047`). Publishes `is_closed`, `open_time`, `close_time`, `outcome_status`, `min_model_confidence` and `final_model_confidence`, `trace_count`, `trace_ids` (`JSON`), `root_error_trace_count`/`failed_trace_count`/`rootless_trace_count`, `closing_trace_id`, and `business_unit` (`outcome.owner` in `app_registry`, else earliest trace owner, else `'__unowned__'`). **`outcome_subject` lives strictly in restricted `outcomes` and is omitted from `outcomes_open`**.

## Access (multi-project split datasets, split SAs & RAPs)

Physical Silver layout (`ADR-048`) separates **four datasets** (`silver_internal`, `silver_ref`, `silver_open`, `silver_restricted`) supporting multi-project Bronze/Silver/Gold estates with independent IAM, location-matched CMEK keys, and `bq-eval bootstrap --mode silver`:
- `silver_internal`: internal `spans(from_time, to_time)` and `trace_aux_agg(from_time, to_time)` TVFs, `jcs_canonicalize` (inline V8 `DETERMINISTIC LANGUAGE js` canonicalizer), `jcs_sha256`, and `jcs_tool_args_sha256` SQL wrappers (native `BYTE_LENGTH <= 65,532` guard and `TO_HEX(SHA256(...))`, zero external connection, CMEK-compatible, `ADR-048`), `unit_entitlements`, and the three `workflow_events` copies (`workflow_events_sor`, `workflow_events_platform`, `workflow_events_app`, clustered by `event_type, outcome_id, trace_id, action_id`). `silver_open` callers have zero access to `silver_internal`; outer published TVFs use 2-hop routine authorization (outer TVFs authorized on `silver_internal`, inner Bronze-reading TVFs authorized on `_AllSpans`/`_AllLogs`, re-applied after every `CREATE OR REPLACE`).
- `silver_ref`: SCD-2 reference tables (`app_registry`, `tools`, `skill_registry`) readable by Silver and Gold.
- `silver_restricted`: `trace_payloads`, `traces`, `tool_calls`, `events`, `outcomes`, Shape-3 BigLake table `shape3_payloads`, and fixed-window wrapper views — each restricted function filters to the caller's `(business_unit, tenant_id)` through `silver_internal.unit_entitlements` keyed on `SESSION_USER()` (fed by CI/directory group-expansion sync; `'*'` wildcard for BU-wide access, explicit `tenant_id` for `UC9`, mapping `NULL` business units to `'__unowned__'` for admin/audit; scheduled Gold jobs run as per-BU Gold service accounts plus an `'__unowned__'` admin/audit SA; `ADR-044`, `ADR-045`, `ADR-047`); **row access policies (RAPs)** cover stored tables.
- `silver_open`: `traces_open`, `tool_calls_open`, `events_open`, `model_calls`, `outcomes_open`, `outcome_links`, and fixed-window wrapper views — zero text, zero raw or hashed user/tenant IDs in single-cloud deployments (`ADR-038`, `ADR-047`), zero business keys, zero argument hashes or file digests, zero Shape-3 bucket scans.
- Window constants (`${READ_MARGIN_MINUTES}` default `60`, `${SETTLE_MINUTES}` default `5`, `${OUTCOME_LOOKBACK_DAYS}` default `30`) render into TVF SQL at deploy time so BigQuery preserves `37x` literal/parameter pruning and every published object keeps the `(from_time, to_time)` signature (`ADR-048`). Each Silver object lives in its own `.sql` file under `sql/silver/`. In the design-only `enterprise` profile, **two separate least-privilege SAs** would populate `silver_open` vs. `silver_restricted` so no single SA bridges both tiers.

## Reference tables & Two-Speed CI/CD Registry Port

`app_registry`, `tools`, and `skill_registry` enforce mandatory SCD-2 validity windows on `RL-1`–`RL-3` and `regulated_worm` workloads, fed by the **Two-Speed CI/CD Dual-Registry Ingestion Port** (automated GitOps sync for additive `RL-3`–`RL-5` manifests; dual-signed `CODEOWNERS`/MRM gates for `RL-1`/`RL-2` promotions, `protected_block_sha256` edits, and capability flag downgrades) plus cloud-registry dark-agent reconciliation.

## Columns and labels

Values Silver or a Gold add-on formula/gate computes, joins, or filters on stay typed columns (`sql/silver/schema/*.json`); pure slice-only attributes (~30 prompt, agent-version, MCP, A2A, cloud-residency, and evaluation-score keys) project into one `labels` `JSON` column registered in `sql/silver/schema/labels_registry.json` (`ADR-039`, `ADR-045`).

## One implementation & Local/CI Eval Runner Port

BigQuery SQL is the single Silver implementation. The offline translator serves both repo verification proofs and the first-class **`< 5s` Local/CI Eval Runner Port** (`CI_ONLY`) running Silver SQL + deterministic Gold `Rule 0` over local OTLP traces for PR gates (`UC8`) and optimizer sweeps (`UC6`). When the translator and BigQuery disagree, BigQuery is right.
