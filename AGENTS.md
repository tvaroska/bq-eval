# Agent Instructions (`bq-eval`)
<!-- doc-tier: full -->

## 1. Purpose & Scope
`bq-eval` (**BQ Eval**) builds a **Bronze and Silver telemetry core in BigQuery** with **Gold add-ons** (evaluation, monitoring, and cost) layered strictly on top ([`specs/layers.md`](specs/layers.md), [`design/bq-eval.md`](design/bq-eval.md)). Telemetry stays in the cloud and perimeter where it landed (multi-region `US`/`EU` Hub default with strict per-domain location/CMEK alignment); Silver normalizes up to three accepted [telemetry shapes](specs/shapes.md), three VPC-SC-isolated `workflow_events` tables (systems of record, platform controls, applications), gateway `inference_request` logs (`requests`), `burst_metrics_1m`, and SCD-2 reference tables (`app_registry`, `tools`, `skill_registry`, `capacity_pools`, `capacity_allocations`, `allowed_models` synced via a Two-Speed CI/CD Dual-Registry Port) into published objects (`model_calls`, `requests`, `tool_calls`, `events`, `trace_payloads`, `traces`, `outcomes`, `outcome_links` over single-pass internal `spans`, split across `silver_open` and `silver_restricted` with split compaction SAs and a per-unit caller filter, running as `light` table functions of an explicit time window, with the high-volume `enterprise` profile design only) that hold counts and facts only: zero prices, zero fabricated defaults, and no pass. Gold add-ons (`agent_eval`) run detective `>= 5m` audits (with PII-free GCS Retention-Lock + CMEK WORM snapshots + per-subject RTBF crypto-shredding, concrete slot breakers, `< 5s` `CI_ONLY` Pareto/Rule-0, Optimizer Gold exports, and versioned `v1.1` exports to `capacity`), while synchronous blocking lives in the Preventive Request-Path Enforcement Port. More than one cloud/region ([`specs/clouds.md`](specs/clouds.md)) and capacity and governance ([`specs/capacity.md`](specs/capacity.md)) are modular extensions.

> **Current state (`docs/roadmap.md`):** Review cut **`v0.7.0-rc1`** ships single-domain GCP Silver core + Silver capacity extension (`22` schemas + `labels_registry.json`), ports all Gold Evaluation, MRM, WORM, Cost, 3-pool `FOCUS 1.2`, Monitoring, and Optimizer views onto Silver only (`bootstrap --mode silver|gold`), retires legacy dual view chains and hand-written SQLite copies, and includes `M20-0` BigQuery `light` hardening (inline V8 `LANGUAGE js` JCS, `< 10`-scan rollups, Split-SA Gold staging). Final `v0.7.0` awaits dual-human domain-expert sheets (`M19-3`) over real semantic edge-case traces.

### Sibling Repository Boundaries
- **`bq-eval` (This Repo)**: Bronze-to-Silver SQL adapters and published Silver objects in BigQuery, plus Gold evaluation (`8` canonical 4-point ordinal rubrics, stratum-specific Rogan-Gladen calibration, dual-blind `AC2` + binary cut-point agreement, paired/live A-B regression gates), monitoring, and cost (`CPVO`, `>200K` `input + cache_read` cliffs, 3-pool `FOCUS 1.2` chargeback + `INFORMATION_SCHEMA.JOBS` reconciliation) add-ons. Other repositories never name `bq-eval` views.
- **`agent-evals`**: Normative cross-repo evaluation standards (`EVAL-P01`–`EVAL-P11`), regulated banking Model Risk Management (`SR 11-7`, `SR 26-2 / OCC 2026-13`) playbooks, `RAIR` / `RSR` / `60-40` audit governance, academic compendiums, and cross-workspace compliance auditing (`eval-audit`).
- **`capacity`**: GSU/GPU capacity sizing optimization, sub-minute 3P burst & quota-cliff physics, gateway YAML/CEL routing/shedding, idle pool reallocation UIs, and `FOCUS 1.2` billing actuation over exported `v1.1` burndown payloads.

### Recording decisions

- A design decision confirmed in conversation is written in the same turn: the requirement in `specs/`, the way it is met in `design/`, and an entry in `DECISIONS.md`.
- What is still undecided goes to `specs/open-questions.md`, with the current leaning.
- `docs/roadmap.md` changes only with explicit approval.
- Leave the changes uncommitted unless asked, and run the gate.

## 3. Canonical Verification Commands

Run the canonical gate script (also invoked directly by [`cloudbuild.yaml`](cloudbuild.yaml), which adds `terraform test`, `docker build`, and `trivy` scan steps):
```bash
bash scripts/gate.sh
```
This checks `uv.lock`, syncs `.venv` against the lockfile, runs `.venv/bin/ast-grep scan --rule specs/ast.rules.yaml`, `ruff format --check`, `ruff check`, `mypy --strict`, `pytest -p no:cacheprovider -v -rs`, and all 10 CLI / runner / blind-kit / example smoke runs (`demo`, `loadgen`, `judge-sql`, `bootstrap --mode silver|gold`, `capacity-export`, `scripts/blind_sme_kit.py export`, `< 5s` Silver + Gold fixture runner smoke, `examples/run_showcase_demo.py`).
